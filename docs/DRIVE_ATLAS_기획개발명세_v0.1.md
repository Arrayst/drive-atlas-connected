# DRIVE ATLAS 기획 개발 명세

개발 명세 v0.1 · 2026년 11월 7일

## 1 개발 방향과 현재 상태

DRIVE ATLAS는 가까운 풍경 좋은 길과 들를 곳을 한 코스로 고르고, 주행 중에는 조작을 줄이며, 도착 후 여행 기록을 모으는 차량용 여행 앱이다. 여행 준비와 기록의 부담을 줄이고, 함께한 경험이 사용자의 차에 대한 애착으로 이어지는지 확인하는 것이 목적이다.

이번 개발의 권고 범위는 검수한 소수 코스의 선택, 내비게이션 연결, 위치 기반 진행 확인, 주차 후 기록 저장까지 이어지는 하나의 흐름이다. DRIVE ATLAS로 개발을 진행하며, Kotlin Compose 기반 Android 시뮬레이터 alpha의 소스, 빌드와 도메인 단위테스트 13개를 완료했다. 실제 SDK 연동, 실차 검증과 제출용 서명 release는 미완료다. 본 문서는 구현 목표와 확인된 상태를 구분하는 개발 기준이다. [S8]

### 먼저 증명할 것

- 사용자가 목적지와 정차 지점을 따로 찾는 수고를 줄일 수 있는가.
- 차량의 제한 상태가 바뀌어도 탐색과 편집을 안전하게 잠글 수 있는가.
- 위치 증거가 부족한 여정을 완주로 과장하지 않고 기록할 수 있는가.
- 저장한 여행 기록이 다음 코스 선택으로 이어지는가.

| 구분 | 현재 상태 | 이 문서의 처리 |
| --- | --- | --- |
| 기존 시연 | 정적 웹과 모의 차량 신호 | 화면 흐름을 설명하는 참고 자료 |
| 네이티브 alpha | 시뮬레이터 빌드와 단위테스트 완료 | 최종 UI 검증 중, 실제 SDK 미연동 |
| 후속 확장 | 계정과 공동여행, 지역 집계 등 | 핵심 흐름 검증 이후 별도 결정 |

### 현재 확보한 개발 근거

기존 시연은 코스 탐색, 상세, 주행 제한, 도착, 브라우저 기록, 계절 모음의 여섯 장면을 제공한다. 실제 위치 접근, 내비게이션, 계정, 백엔드 및 차량 SDK 연결은 없다. 코스와 장소, 거리와 시간도 예시다. 상태 전환 테스트 15개는 통과했다. 별도의 Android alpha는 debug APK와 unsigned release 빌드, 도메인 테스트 13개, lint 오류 0건을 확인했다. 이 결과는 실제 주행이나 플랫폼 연동 검증을 대신하지 않는다. [S1][S2][S8]

## 2 사용자 문제와 제품 가설

### 우선 대상

주말에 가까운 지역으로 반나절 또는 하루 드라이브를 가려는 커플, 친구, 가족을 우선 대상으로 한다. 동행 형태와 무관하게 이용할 수 있으며, 자녀 정보나 가족 구성 입력을 필수로 요구하지 않는다. 운전자는 출발 전 선택을 마치고, 주행 중에는 기존 내비게이션 안내에 집중한다.

### 해결하려는 문제

- 준비가 흩어져 있다. 풍경 좋은 길, 식당, 산책 장소, 주차 가능 여부를 각각 찾은 뒤 다시 내비게이션에 옮겨야 한다.
- 운전 중 선택 부담이 생긴다. 새로운 장소를 찾거나 사진을 고르는 행동이 운전과 충돌할 수 있다.
- 여행 뒤 맥락이 사라진다. 사진은 남아도 어느 길을 누구와 어떤 차로 다녀왔는지 쉽게 돌아보기 어렵다.

위 문제는 사용자 조사로 확인할 가설이다. 현재 자료만으로 수요 규모, 재방문 효과, 브랜드 충성도 향상을 입증했다고 표현하지 않는다.

### 핵심 가치

출발 전에는 이유가 있는 코스를 보여준다. 계절 풍경과 정차 가능한 장소, 코스 길이, 예상 주행시간, 정보 갱신일을 함께 제시한다. 주행 중에는 화면을 더 보게 만들지 않고, 도착 후에는 완주 여부와 무관하게 여행의 기억을 남길 수 있도록 한다.

| 구간 | 사용자에게 주는 가치 | 관찰할 신호 |
| --- | --- | --- |
| 출발 전 | 코스와 정차 지점을 함께 선택 | 선택 과정의 시간과 막히는 지점 |
| 주행 중 | 탐색 없이 진행 상태 유지 | 불필요한 화면 조작 유도 여부 |
| 주차 후 | 기록과 완주 근거를 구분 | 저장 성공과 판정 설명 이해 |
| 다음 여행 | 지난 기록에서 다음 코스 탐색 | 다음 코스를 고르는 행동 |

### 초기 검증 방법

팀이 확보한 소규모 참가자에게 같은 여행 준비 과제를 주고, 기존 방식과 제안 흐름을 비교한다. 선택 이유, 정보 부족, 인증 보류 이해 여부를 인터뷰로 확인한다. 참가자 수와 목표치는 모집 가능성과 기준 데이터를 확인한 뒤 정하며, 시연 중 클릭 수를 실제 이용 성과로 보고하지 않는다.

## 3 전체 이용 흐름과 화면

출발 전 선택부터 주차 후 저장까지 연결하되, 정차한 상태에서만 상세 탐색을 허용한다. 주행 상태와 여행 진행 상태는 별도로 관리한다. 코스의 끝에 도달했다고 앱이 주차 상태로 바꾸어서는 안 된다.

| 단계 | 화면과 행동 | 다음 단계의 조건 |
| --- | --- | --- |
| 1 발견 | 지역과 계절에 맞는 검수 코스 탐색 | 상세 탐색이 허용된 정차 상태 |
| 2 선택 | 코스 이유와 정차점 확인 후 출발 | 지원 기능과 위치 동의 확인 |
| 3 연결 | 목적지와 지원되는 경유지 전달 | 실제 내비 요청 결과 확인 |
| 4 진행 | 기존 내비 안내 중심으로 이동 | 백그라운드에서 위치 근거 평가 |
| 5 도착 | 도착 후보와 주차 여부를 따로 확인 | 정차가 확인되어야 결과 화면 허용 |
| 6 기록 | 완주 또는 미확인 기록을 저장 | 동일 여정의 중복 저장 방지 |
| 7 재방문 | 기록 열람과 다음 계절 코스 선택 | 정차 상태에서만 탐색 |

### 화면별 최소 정보

- 발견과 상세: 코스명, 선정 이유, 거리와 주행시간의 기준, 정차 지점, 주차 관련 정보, 출처와 갱신일. 실제 검증 전에는 예시 표시를 유지한다.
- 주행: 플랫폼이 허용하는 최소 상태만 표시한다. 자체 턴바이턴 안내나 지도 조작을 구현하기보다 공식 내비 연결을 우선 검토한다.
- 도착과 기록: 여정 날짜, 코스, 판정 상태, 판정 이유, 저장 결과. 자동 생성 카드는 텍스트와 검수된 코스 이미지로 시작한다.

### 정상 흐름의 예

정차 상태에서 해안 코스를 고른다. 앱이 지원되는 내비 연결을 요청하고, 응답이 확인되면 여정을 시작한다. 위치가 유효한 동안 정해진 순서의 구간 통과 근거를 모은다. 마지막 구간 도달 후에도 주행 제한을 유지하고, 별도로 정차가 확인되면 결과와 저장 화면을 연다.

### 실패 흐름의 예

위치 권한을 거부해도 코스를 둘러볼 수 있다. 내비 연결이 실패하면 시작 성공으로 표시하지 않는다. 진행 중 위치가 끊기면 완주 판정을 보류하고, 주차 후 미확인 기록으로 저장할 수 있게 한다. 제한 상태를 알 수 없는 동안에는 상세 화면을 열지 않는다.

## 4 최소 기능과 제외 범위

첫 구현은 운영 규모보다 끝까지 동작하는 흐름에 집중한다. 코스 수는 초기 3개를 제안하며, 실제 지명과 주행 안내는 내용 검수 및 지도 서비스 이용 조건 확인 후 적용한다. 아래의 완료 조건은 전체 MVP의 인수 목표다. 시뮬레이터 alpha의 빌드 성공만으로 모두 완료된 것은 아니다.

| ID | MVP 요구사항 | 완료 조건 |
| --- | --- | --- |
| M01 | 검수 코스와 정차점 목록 | 출처와 갱신일, 예시 여부가 보인다 |
| M02 | 정차 중 코스 상세와 선택 | 주행 또는 미확인 상태에서 접근 차단 |
| M03 | 공식 내비 연결 어댑터 | 지원 여부와 성공 또는 실패를 구분 |
| M04 | 위치 기반 여정 진행 | 정책에 맞는 순서와 품질의 근거 확보 |
| M05 | 완주와 미확인 기록 분리 | 근거 부족 시 완주 배지를 발급하지 않음 |
| M06 | 도감과 SNS용 기본 포토카드 | 기기 내 저장과 카드 생성, 외부 자동 게시 없음 |
| M07 | 예외 처리와 진단 | 권한 거부, 신호 소실, 저장 실패 재현 |
| M08 | 코스 재탐색 | 저장한 기록에서 다음 코스로 이동 |

### 첫 구현에서 제외할 기능

- 로그인, 차량 간 계정 동기화, 소셜 피드, 공개 랭킹과 실물 보상.
- 자동 사진 수집, 블랙박스 접근, 얼굴 인식, 동행자 프로필 수집.
- 음성 비서, 음악 또는 영상 재생, 생성형 AI의 실시간 경로 생성.
- 조향, 가감속, 차량 잠금 등 차량 제어와 운전 판단 지원.
- 식당 예약과 결제, 지역 제휴 계약, 쿠폰 발행, 운영자용 대규모 관리 도구.

### 기존 기능과 확장 순서

기존 10개 기능 중 코스 탐색과 완주, 도감, 맛집·카페·포토스팟, SNS 포토카드를 MVP로 유지한다. 기본 카드는 코스 이미지로 생성하고 사진 추가는 선택이다. 플레이리스트, 타이밍드라이브, 시크릿 드라이브, 시즌도감, 연대기, 공동여행은 확장 항목으로 둔다. 사진 촬영이나 위험한 정차를 완주 조건으로 삼지 않는다. [S4]

### 기능을 줄이는 기준

SDK에서 지원되지 않는 경유지 전달이나 차량 데이터는 화면 약속에서 제거한다. 기능이 없을 때 성공처럼 보이는 대체 동작을 만들지 않고, 명시적인 모의 모드와 실연동 모드를 나눈다. 지원 범위가 부족하면 시연 목표를 축소하고 문서도 함께 수정한다.

## 5 주행 안전과 완주 판정

### 제한 상태를 모르면 잠근다

안전 상태는 PARKED_ALLOWED, RESTRICTED, UNKNOWN의 세 가지로 관리한다. 플랫폼의 공식 제한 신호와 정차 근거가 함께 유효할 때만 상세 탐색을 허용한다. 앱 시작, 재연결, 이벤트 누락, 신호 만료는 UNKNOWN으로 두고 잠금 상태를 유지한다. 속도 0이나 목적지 도착만으로 정차 허용을 판단하지 않는다.

| 상태 | 허용하는 화면 | 막아야 하는 동작 |
| --- | --- | --- |
| PARKED_ALLOWED | 코스 탐색, 결과, 기록 관리 | 플랫폼이 추가로 금지한 기능 |
| RESTRICTED | 허용된 최소 상태 안내 | 탐색, 사진, 편집, 보상 연출 |
| UNKNOWN | 확인 불가 안내와 제한 화면 | 상세 화면 해제와 입력 재개 |

화면 버튼뿐 아니라 딥링크, 뒤로 가기, 복원된 화면과 비동기 응답에도 같은 제한을 적용한다. 운전자가 앱 안에서 “주차” 버튼을 누르는 방식으로 잠금을 해제하지 않는다. 모의 신호 변경 도구는 개발용 빌드에만 두고 실제 주행용 빌드에서는 제거한다.

### 완주 증거의 최소 조건

- 출발한 코스 버전과 여정 ID가 고정되어 있고, 유효한 시작 근거가 있어야 한다.
- 위치의 시각, 정확도와 신뢰도를 확인하고, 필수 구간을 정해진 순서대로 통과했는지 평가한다. 시작점과 종점만 같은 이동은 인정하지 않는다.
- 오래된 좌표, 큰 위치 점프, 필수 구간의 수신 공백을 배제한다. 차량 주행거리는 가능한 경우 보조 근거로만 쓰며 단독으로 완주를 인증하지 않는다.
- 판정은 VERIFIED, UNVERIFIED, IN_PROGRESS로 구분하고 이유를 남긴다. 주차 여부는 결과 표시 조건이며, 위치 근거를 대신하지 않는다.

### 검증 정책과 경계

허용 정확도, 구간 반경, 좌표 유효 시간, 필수 구간 범위와 수신 공백 한도는 코스별 시험으로 확정하고 정책 버전에 기록한다. 값이 정해지지 않은 실연동 구성에서는 인증을 발급하지 않는다. 한 번 누락된 필수 근거가 단순 신호 복구로 충족된 것으로 바뀌지 않게 한다.

기기 내 판정은 위변조 방지 인증 서비스가 아니다. 개발용 가상 좌표는 모의 배지로만 표시하고, 실제 보상이나 대외적인 방문 증명에 사용하지 않는다. 완주를 위해 운전자에게 우회, 과속, 급정차 또는 주행 중 조작을 요구하지 않는다.

## 6 구조와 외부 기능 연결

Kotlin Compose 기반 Android 앱에서 화면과 여행 규칙을 외부 SDK와 분리한다. API 35, minSdk 28, JDK 17, Gradle 8.10.2를 작업 기준으로 삼고, 실제 연동은 아래 계약으로 검증한다. 정적 웹의 화면과 모의 로직을 옮기는 것만으로 차량 연동이 끝난 것은 아니다.

### 제안 구조

- 화면 계층: 발견, 상세, 제한 화면, 결과, 기록. 공통 안전 게이트를 거쳐 사용자 동작을 처리한다.
- 여정 계층: JourneyStateMachine, CompletionEvaluator, CourseCatalog. 화면과 독립적으로 진행 상태와 판정 이유를 관리한다.
- 어댑터 계층: 차량 제한, 위치, 내비게이션, 선택적 주행거리 입력을 공통 계약으로 변환한다.
- 저장 계층: 기기 내 코스 캐시, 여정 요약, 판정 근거 요약. 네트워크 없이도 저장한 기록을 읽을 수 있게 한다.

| 경계 이름 | 입출력 계약 | 실패 시 처리 |
| --- | --- | --- |
| SafetyAdapter | 허용 또는 제한과 수신 시각 | UNKNOWN으로 전환하고 잠금 |
| LocationAdapter | 위치, 시각, 정확도·신뢰도, 출처 | 미수신 표시와 판정 보류 |
| NavigationAdapter | 목적지, 경유지와 요청 결과 | 오류 표시와 출발 상태 유지 |
| VehicleAdapter | 지원되는 경우의 주행거리 | 값 없음으로 처리하며 추정 금지 |
| JourneyStore | 여정 ID 기반 저장과 조회 | 저장 실패 표시와 재시도 제공 |

### 연동 후보와 확인 순서

Pleos 이미지 2.1.0, Android 14 ARM64, VehicleSDK 2.3.2 환경이 있으며, 기존 샘플의 빌드와 일부 Vehicle 검증은 본 앱의 연동 증거와 구분한다. NaviHelper 3.0.5의 목적지·경유지·콜백 명세는 확인됐지만, NAVI_ROUTE와 NAVI_ROUTE_SEARCH 권한은 기존 기록에서 승인 대기였다. [S5][S7]

FusedLocation 1.1.3은 isSupported, 위치 시각의 신선도, confidence, null과 오류를 확인한다. 반환된 기존 위치가 새로 계산된 최신 위치라고 가정하지 않는다. pleos.car.permission.FUSED_LOCATION은 dangerous 권한이며 승인 전 호출을 성공으로 처리하지 않는다. [S7]

### 모의와 실연동의 분리

MockAdapter와 실제 어댑터의 빌드 구성을 분리하고 실행 모드를 표시한다. 모의 기록은 실제 기록으로 승격하지 않는다. 재시작 후에도 입력 출처를 보존하며, 실제 어댑터 결과가 없으면 성공값을 채우지 않는다.

공개 Vehicle API 조사에서 실제 속도 getter는 확인되지 않았다. 크루즈 목표 속도를 실제 속도로 대체하지 않는다. TTS와 STT는 client ID와 secret이 필요한 확장으로 두고, 현재 지원 완료로 표시하지 않는다. MVP는 로컬 저장을 기본으로 하며 계정 백엔드는 별도 범위다. [S5]

## 7 데이터와 개인정보 설계

### 수집을 기능에 필요한 만큼으로 줄인다

첫 구현은 계정 없는 기기 내 저장을 기본으로 제안한다. 실시간 주변 추천은 사용자가 위치 이용에 동의했을 때만 제공하며, 동의하지 않으면 지역 직접 선택과 예시 코스를 보여준다. 위치 권한이 앱 전체 이용의 필수 조건이 되지 않게 한다.

| 데이터 | 최소 필드 | 저장과 사용 원칙 |
| --- | --- | --- |
| Course | ID, 버전, 코스와 구간, 출처, 갱신일 | 검수된 정적 데이터로 시작 |
| Journey | ID, 코스 버전, 시작과 종료, 모드 | 진행 복원과 중복 저장 방지 |
| EvidenceSummary | 구간 결과, 품질 사유, 정책 버전 | 판정 설명에 필요한 요약만 유지 |
| Memory | 날짜, 코스, 판정, 기본 카드 | 사용자가 기기에서 개별 삭제 |
| LocationSample | 좌표, 시각, 정확도·신뢰도, 출처 | 원시 궤적은 기본 영구 보관 제외 |

### 위치와 기록의 생명주기

위치 샘플은 여정 진행과 판정에 필요한 동안만 처리하고, 완료 시에는 구간 통과와 실패 이유의 요약을 남긴다. 중단 복구를 위해 임시 저장이 필요하면 플랫폼의 앱 전용 저장소를 사용하고, 여정 종료 또는 취소 시 정리한다. 구체적인 임시 보관 만료 정책은 SDK 검증 단계에서 정하고 시험한다.

여정 도중 앱이 종료되면 재실행 시 안전 상태를 다시 확인한다. 유효한 복구 근거가 없는 구간을 임의로 채우지 않는다. 완료된 기록은 원자적으로 저장하고, 같은 여정 ID에 대한 재시도는 기존 기록을 갱신하거나 그대로 반환하여 중복을 막는다.

### 사용자가 이해하고 통제할 수 있게

- 위치 권한 화면에 이용 목적과 권한 거부 시 가능한 기능을 간단히 안내한다.
- 기록의 완주 판정과 사용자가 직접 남긴 메모를 구별한다. 사진은 선택 기능이며, 얼굴이나 동행자 정보를 필수로 수집하지 않는다.
- 개별 기록 삭제와 전체 로컬 기록 삭제를 제공한다. 최종 삭제 전에는 대상과 영향을 확인한다.
- 사진 첨부를 구현할 경우 선택한 파일만 받고, 위치 메타데이터와 외부 전송 여부를 별도로 검토한다.

### 진단 정보의 최소화

기본 로그는 이벤트 종류, 결과 코드, 실행 모드와 정책 버전을 중심으로 남긴다. 정밀 좌표, 차량 식별번호, 계정 식별자, 사진 원본을 진단 로그에 넣지 않는다. 테스트를 위해 상세 위치가 꼭 필요하면 수집 목적과 기간을 정하고 별도 동의를 받는다. 계정과 클라우드가 없는 MVP에서도 기기 백업과 로그의 실제 노출 범위를 확인한다.

## 8 인수 기준과 테스트 행렬

화면이 연결되는 것과 실제 연동이 검증되는 것을 따로 기록한다. 아래 항목은 자동 테스트, 에뮬레이터와 허용된 시험 환경에서 재현하며, 결과에는 빌드 버전, 실행 모드, 플랫폼과 입력 출처를 함께 남긴다.

| ID | 입력 또는 상황 | 기대 결과와 확인 증거 |
| --- | --- | --- |
| T01 | 정상 코스 선택과 여정 종료 | 선택부터 저장까지 연결되고 재시작 후 기록 유지 |
| T02 | 위치 권한 거부 | 예시 또는 직접 지역 선택 제공, 완주 미발급 |
| T03 | 필수 구간에서 위치 소실 후 복구 | 누락 근거가 복구만으로 유효해지지 않음 |
| T04 | 오래된 좌표, 낮은 신뢰도, 위치 점프 | 진행과 인증에 사용하지 않고 이유 기록 |
| T05 | 구간 순서 변경 또는 종점만 도달 | 순서와 범위 미충족으로 완주 미발급 |
| T06 | 주행거리만 증가 | 거리값만으로 진행 완료나 완주 전환 금지 |
| T07 | 주행 제한, 상태 미확인, 신호 만료 | 탐색과 편집 차단, 복원 화면도 같은 제한 적용 |
| T08 | 도착했지만 주행 제한 유지 | 도착 후보만 기록하고 결과 연출을 열지 않음 |
| T09 | 내비 미지원, 실패, 응답 지연 | 성공으로 표시하지 않고 재시도 또는 취소 제공 |

| T11 | 저장 공간 부족과 손상 데이터 | 오류를 알리고 기존 정상 기록을 보존 |
| T12 | 모의 모드, 실제 모드와 기록 삭제 | 출처 혼동 없음, 삭제 대상만 제거 |
| T13 | 기본 카드 생성과 선택 사진 | 사진 없이도 카드 생성, 외부 자동 게시 없음 |

### 배포 전 통과 조건

정상 흐름과 안전 관련 T02~T09를 모두 통과하고, 지원하지 않는 기능은 화면에서 비활성화하거나 제외한다. SDK 호출 로그와 실제 화면 결과가 맞아야 한다. 안전 제한이 해제되는 버그나 근거 없는 완주 판정이 남아 있으면 실연동 시연을 진행하지 않는다.

### 현재 증거와 다음 증거

웹 시연의 15개 테스트는 정적 웹 내부 상태를 검증한다. 웹의 도착 시연 버튼은 진행값을 끝으로 이동시키므로 완주 근거가 아니다. Android 시뮬레이터 alpha는 별도 도메인 단위테스트 13개를 통과했고, 앱 ID와 모의 출처 구분, 재시작 시 UNKNOWN 잠금 등을 구현했다. 이 13개 단위테스트는 위 인수 시나리오 전체 통과를 뜻하지 않는다. 실제 SDK 호출과 최종 UI 검증은 별도다. [S2][S8]

## 9 구현 단계와 장기 확장

진행 순서는 범위 확인, 실행 골격, 핵심 흐름, 증거 검증, 제출 준비다. 개발 일정을 약속하기보다 단계별 통과 조건을 관리한다. 남은 시간에 맞춰 범위를 줄여도 안전 제한과 기능 상태의 정직한 표시는 유지한다.

| 단계 | 산출물 | 통과 조건 |
| --- | --- | --- |
| 1 개발 기준 | 실제 저장소와 브랜치, SDK 계약 | 팀 접근과 권한, 구현 범위를 확인 |
| 2 실행 골격 | Kotlin 앱과 어댑터 | 대상 환경에서 실행하고 실패를 구분 |
| 3 핵심 흐름 | 코스, 진행, 도감과 기본 카드 | 정상 흐름과 예외가 함께 동작 |
| 4 검증 | 판정 정책과 테스트 결과 | 안전과 근거 누락 사례를 통과 |
| 5 제출 준비 | 공식 기획서, 실행물과 영상 | 표현과 실행 결과, 접근 권한 일치 |

### 지역 수요 분석은 별도 동의를 받는 확장

코스 선택과 실제 방문의 집계를 지역 수요 또는 현대·기아의 투자 검토 참고로 활용하는 방향을 검토할 수 있다. 서비스 기록에 필요한 동의와 선택적 분석 동의를 분리하고, 동의하지 않아도 핵심 기능을 이용하게 한다. MVP에는 외부 리포트와 분석 전송을 넣지 않는다. [S4]

- 지역 또는 코스 단위로 최소 집계하고, 소수 집단은 숨기거나 상위 지역으로 합친다. 임계값과 기간은 재식별 위험을 검토해 결정한다.
- 원시 이동 궤적, 개인별 방문 이력, 차량 식별정보를 보고서에 넣지 않는다. 단순 통과나 교통 정체를 실제 방문과 동일하게 계산하지 않는다.
- 이용자 표본, 계절, 추천 노출에 따른 편향과 데이터 누락을 표시한다. 현장 조사와 사업성 조사 전에는 투자 결정자료가 아닌 참고자료로만 설명한다.

### 사업성과 확장 가설

지자체 협업, 프리미엄 도감, 집계 리포트는 수익 가설이며 체결한 제휴나 수익 실적으로 표현하지 않는다. 플레이리스트와 음성, 공동여행은 플랫폼 지원·권한·개인정보 범위를 확인한 뒤 개별 기능으로 검증한다.

### 남은 결정

팀 저장소와 검토 방식, 실제 코스와 자료 사용 권한, 내비 권한, 안전 제한 신호, 위치 판정 임계값, 임시 위치 보관 기간, 포토카드의 선택 사진 범위를 확정한다. 기획 원문, 요구사항 ID, 어댑터 계약, 테스트 결과와 알려진 제한을 같은 브랜치에서 관리한다.
