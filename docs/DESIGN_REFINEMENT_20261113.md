# DRIVE ATLAS 화면 정리 · 2026-11-13

## 목표와 범위

기존 동작을 유지하면서 과한 색 면, 중복 제목·설명, 행동 버튼이 아래로 밀리는 배치, 실제 내비와 SIM의 혼동을 줄였다. `e0af412b73e7e9344c25ee34979de7eee4cbdcfe` 기준 로컬 변경이다. 기존 사용자 작업과 데이터를 보존했고 원격 푸시·배포·제출은 하지 않았다.

## 반영한 변경

- **홈·추천길:** 사진 → 지역 → 이름 → 코스 거리·시간 순서로 정리했다. 큰 파란 선택 면과 중복 순번 대신 흰 카드·선택 테두리·체크를 사용한다. 코스 시간은 지도 위, 포함 범위는 지도 아래에 묶었다. 필터 행 간격과 선택 표현을 통일했다.
- **코스 상세:** 지도·코스 기준점·SIM 미리보기가 먼저 보이도록 사진을 아래로 옮겼다. 지도 번호와 기준점 목록의 관계를 명시했고 출처·도로 기준점 주의는 유지했다.
- **지도:** 오프라인 복귀를 명확한 주요 버튼으로 만들고, 그 자리에서 장소 목록으로 갈 수 있다. 선택 필터는 배경·굵기·밑줄·접근성 선택 상태를 갖는다. 장소 목록 행에는 이동 표시를 넣었다.
- **가족 비교:** 전체 일정·남는 시간·확인할 조건·다음 행동을 상세 시간표보다 먼저 배치했다. 충족/추가 확인/조정 필요를 문구와 녹색/황갈색/적색으로 구분한다. 시간 미입력을 0분이나 확정 총시간으로 표현하지 않는다.
- **왕복 시간:** 계산/적용/취소 행동이 구간 상세보다 먼저 보인다. ‘왕복 시간 계산 · 전송 정보 확인’으로 목적과 확인 단계를 함께 표시한다. 현재 위치가 아닌 공개 기준점이라는 설명과 요청별 동의는 유지했다.
- **여행 기억·만족도:** 기록 목록에 더 많은 폭을 주고 부연 설명은 펼치기로 정리했다. 평점·뜻·느낌·기록 종류·날짜를 읽기 순서대로 배치했다. 만족도 다섯 선택지를 균등하게 만들고 큰 빈 공간의 입력 모달을 내용 높이에 맞췄다. 파란 주요 버튼에서 상위 텍스트 스타일 때문에 검은 글씨가 보이던 문제를 수정했다.
- **다녀온 길·우표:** 모의 기록임을 제목 설명에서 명시하고 과한 어두운 배너/선택 면을 줄였다. SIM와 실제 방문 인증을 혼동하지 않도록 유지했다.
- **SIM·외부 내비:** SIM의 설정 진입 시 긴 탐색 메뉴를 건너뛰고 설정을 바로 표시한다. 일반 메뉴 재진입은 별도로 동작한다. 시작 문구는 ‘SIM 경로 계산·재생’, 기본 내비 열기는 ‘목적지 미전송’을 명시한다.
- **반응형:** 좁은 폭/큰 글씨에서 제목·시간과 구간 상세를 세로 배치한다. 좁은 코스 카드의 사진을 숨겨 제목 공간을 확보하고 기억의 느낌 태그도 별도 줄로 배치한다.

## 바꾸지 않은 동작

P 기어·플랫폼 UX 제한, 지도/위치/경로 동의, 가족 순위 계산, 기억 저장 조건·500개 제한·삭제 확인, 내비 전송·성공 검증, 실제/SIM 구분은 유지했다. 사진 및 지도 출처도 유지했다. 실제 차량을 조작하거나 새 위치 권한·지도 연결 동의를 승인하지 않았다.

## 검증과 증거

- 최종 소스: 단위 테스트 **293개 통과**, 실패/오류/건너뜀 0개.
- `lintDebug`: 오류 0개, 경고 18개, 정보 2개. 기존 경고를 해결했다고 주장하지 않는다.
- `assembleDebug`, `assembleRelease` 성공. 릴리스 APK는 기존과 같이 미서명이다.
- 빌드 로그: `evidence/design-refinement-20261113/build-records-layout.log`.
- 표준 디버그 APK: `app/build/outputs/apk/debug/app-debug.apk`. 별도 검수 패키지를 만든 뒤 표준 앱 ID로 산출물을 다시 생성했다. SHA256 `5e6ee22ff54ac49d35c7df9fa85efc69d374f197de86d5bb86a0e58bd4062053`.
- 기존 데이터 유지 설치 후 PLEOS의 실제 분할 창에서 렌더를 확인했다. 초기 회귀 검증은 코스 3개, 오프라인 복귀, 가족/시간 편집 취소, 미확정 시간, 내비 대화상자 취소, 만족도 취소, 기록·우표 이동, 키보드 포커스를 포함한다.
- 이후 전체 화면 검수는 **별도 `com.driveatlas.connected.designreview` 패키지**에서 수행했다. 새 앱 기본값과 명시적 합성 `QA 시연 차량`/SIM 기록만 사용했고, 기존 앱 저장소를 복사하지 않았다. 지도는 동의 전 상태로 두었다.
- 전체 검수 캡처는 47장(번호 21 제외)이다. 주요 실제 UI 회귀 5개와 추가 걷기 선택·기록 지도 회귀 2건이 통과했고, 합성 가족/여정 저장 파일은 검수 전후 바이트가 동일하다.
- Gemini 검수용 실제 PNG·UI XML: `evidence/design-refinement-20261113/gemini-safe/`. 화면별 상태는 `screens.json`, 데이터·빌드 이력은 `MANIFEST.md`, 마지막 회귀 결과는 `final-ui-run.log`와 `ui-checks.json`에 있다. 캡처는 목업이 아닌 실제 에뮬레이터 렌더다.
- 주요 전후 비교: 홈 `before-home.png`/최종 `after-home.png`, 코스 상세 `before-detail-pass2.png`/`gemini-safe/05-course-detail.png`, 왕복 시간 `after-eta.png`(2차 전)/`gemini-safe/38-roundtrip-final.png`, 기억 입력 `after-rating.png`(2차 전)/`gemini-safe/17-rating-empty.png`, SIM 설정 `gemini-safe/08-sim-settings.png`/`gemini-safe/37-sim-settings-refined.png`.
- Gemini 의견은 실제 화면·소스와 대조했다. 이미 있는 구분선/버튼을 없다고 보거나 SIM 기록 선택 자체를 없애자는 제안은 반영하지 않았다.

## 확인하지 않은 범위

실차 인증·주행 안전성·라이브 교통 ETA·외부 내비의 실제 길안내·음성 재생 성공은 이번 검증 범위가 아니다. 네트워크 요청 동의창은 취소했고 새 요청을 보내지 않았다. 지도 연결 승인 뒤에 있는 SIM 경로 요청 확인창은 승인/우회 없이 소스만 확인했다. 좁은 기기·큰 글씨·IME 전체 조합은 코드 리뷰로 보완했으며 별도 기기의 실제 렌더 통과로 주장하지 않는다.

테스트 중 PLEOS의 소프트웨어 렌더러에서 발생한 차량 셸 크래시는 앱 결함과 구분했고, 동일 에뮬레이터를 호스트 GPU 모드로 실행해 안정화한 뒤 화면 검증을 수행했다.

## 추가 회귀 수정

### 걷기 한도 선택지
걷기 30분이 기본 목록에 없고 현재값만 앞에 임시 삽입되어, 30→0→10→20→40 순서로 표시되고 다른 값을 누르면 30분이 사라졌다. 기본 30분을 포함하고 공통 시간 선택지는 숫자 오름차순·중복 제거를 적용했다. 편집 진입 시의 값은 선택 변경 뒤에도 보존한다. `PlanningTimeOptionsTest` 6개로 비표준 복원값·미설정 문구·중복·재선택을 검증했다.

실제 QA에서 0·10·20·30·40 순서와 checked 상태 30→20→30을 매 단계 확인했다. `gemini-safe/45-walk-thirty-in-order.png`부터 `47-walk-thirty-reselected.png`, `walk-options-run.log`, `walk-option-checks.json`에 증거가 있다. 저장 없이 닫았고 기존 25/26은 수정 전 증거로 유지했다.

### 기록 지도 두 열 배치
넓은 화면에서 지도와 목록의 폭을 각각 소수 배율로 계산하면 픽셀 반올림 합계가 1px 초과해 FlowRow의 목록이 아래로 내려갔다. 넓은 폭은 Row의 weight(0.65/0.35), 좁은 폭은 Column으로 명시 분기했다. 날짜·상태 기록 목록은 유지했다. 수정 후 증거는 `gemini-safe/48-records-map-side-by-side.png`, 검증 로그는 `records-layout-run.log` 및 `records-layout-checks.json`이다.
