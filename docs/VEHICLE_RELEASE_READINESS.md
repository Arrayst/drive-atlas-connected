# DRIVE ATLAS 실차 검증·배포 준비 체크리스트

확인일: 2026-11-11. 이 문서는 준비 계획이며 실차 인증서나 출시 승인서가 아니다. 동시 개발 중인 자동 왕복시간 기능의 최종 구현·테스트 결과는 해당 기능 문서와 최종 빌드 결과를 별도로 확인한다.

## 지금 확인된 상태

- 사용자는 2026-11-11 별도로 실제 시험 차량을 사용할 수 없다고 밝혔다. 읽기 전용 `adb devices -l` 결과도 `emulator-5580 / Car_on_arm64_emulator` 한 대뿐이다. 현재 범위는 에뮬레이터와 코드 검증이며 실차 시험은 **Not Run(미실행)** 이다. 사용자에게 지금 시험 차량 확보를 요구하지 않는다.
- 기존 기록상 단위 테스트 81개, lint 오류 0개, debug 및 unsigned release 빌드가 통과했다. 이번 문서 작업에서 재실행한 결과가 아니며 새 변경의 검증을 대신하지 않는다.
- `com.driveatlas.connected.emulator`는 개발용, `com.driveatlas.connected`는 release 패키지다. 확인 시점 Gradle에는 release signing 설정이 없고 `SIMULATOR=false`만 지정되어 있다. 미서명 APK를 실차 설치 가능·스토어 제출 가능 상태로 표현하지 않는다.
- 에뮬레이터에서 담양의 개별 목적지 3개 안내 확인은 통과했지만 전체 코스 응답의 경유지 좌표가 `(0,0)`인 공급자 문제가 남아 있다. 전체 코스 순차 안내·실제 방문을 확인한 것은 아니다. 근거: `NATIVE_NAVIGATION_V08.md`.
- 실제 위치 접근·실차 운행·계정 생성·권한 확대·키 생성·배포·계약·결제는 이 준비 작업에서 수행하지 않았다.

## 지금 진행할 범위: 차량 없이 가능한 검증

현재 개발·에뮬레이터 검증을 계속하기 위해 사용자가 차량을 구하거나 실차 일정·운영자를 제공할 필요는 없다. 자동 왕복시간과 실패 처리, 단위 테스트/lint/build, 에뮬레이터에서 가능한 화면·생명주기·서비스 연동 회귀 시험을 우선 완료한다. 권한이나 보안 제한으로 실행할 수 없는 상태 전환은 우회하지 않고 단위 테스트 근거와 미실행 항목을 구분해 남긴다. 실제 결과는 최종 기능 문서에 기록하며 에뮬레이터 성공을 실차 성공으로 바꾸어 쓰지 않는다.

기존 계정/프로젝트가 있다면 공개 가능한 SDK 이용 상태는 향후 배포 판단에 도움이 되지만, 계정 생성·키 준비·정책 게시·스토어 제출은 현재 개발을 진행하기 위한 사용자 필수 작업이 아니다. 배포 또는 제휴 단계로 넘어가기로 정할 때 필요한 선택만 별도로 확인한다.

## 향후 정식 출시·제휴 단계의 선택적 선행조건

아래 항목은 **지금 사용자에게 요구하는 준비 목록이 아니다.** 향후 공급자/파트너와 공식 실물 검증 기회가 생기거나 출시를 진행하기로 결정했을 때 확인할 조건이다. 현재는 장비 확보를 기다리지 않고 독립적인 에뮬레이터 작업을 계속한다.

1. **테스트할 차량 또는 실물 IVI와 공식 테스트 경로.** 모델·연식·지역, Pleos Connect/IVI 소프트웨어 버전, 차량 소유자 또는 장비 관리자 허가, 테스트 가능 장소·일정을 확인한다. 일반 Android Auto 지원이나 USB 연결만으로 이 앱의 지원을 판단할 수 없다. Pleos Connect SDK 서비스가 있는 지원 장비가 필요하다. 벤치 IVI만으로 실제 차량 신호·GPS·주행 검증을 대체할 수도 없다.
2. **해당 장비에 대한 공급자 승인 설치 절차.** 공급자·프로그램 담당자가 허용한 테스트 채널, 앱 서명 요구사항 및 연결 방식을 확보한다. 공개 자료에서 일반 소비자 차량에 대한 임의 ADB sideload 허용은 확인하지 못했다. 개발자 모드·USB 디버깅·보안 설정을 임의로 켜거나 권한을 강제 부여하지 않는다. 장비 확보가 안 되면 에뮬레이터 검증까지만 완료로 표시한다.
3. **기존 Pleos 계정/프로젝트의 존재와 SDK 사용 가능 상태.** 비밀번호·Client Secret·서명키를 채팅이나 저장소로 전달하지 않는다. 기존 계정이 있으면 새 계정부터 만들 필요가 없다. 프로젝트 소유자, 앱 카테고리와 지원 지역을 정하고 실제 콘솔의 SDK 상태를 확인한다. 새 계정·약관·SDK 신청·제휴 계약은 승인된 별도 단계다.
4. **실차 위치 사용 동의와 테스트 운영자.** 운전자가 운행 중 화면을 조작하지 않도록 운전자와 동승 관찰자를 구분한다. 먼저 주차 상태에서 확인하고, 승인된 안전한 시험 환경에서만 상태 전환·주행 시험을 진행한다. 실제 GPS 읽기, 외부 경로 서비스에 위치 전송, 시험 로그 공유는 각각 범위·대상을 먼저 정한다. 기존 에뮬레이터 GPS 허용을 실차 위치나 외부 전송 허용으로 확대 해석하지 않는다.
5. **출시할 때의 책임자·서명·지원 정보.** 배포 주체, 고객지원 연락처, 출시 국가, 운영 가능한 정책 URL, 기존 배포키 보유 여부와 보관 책임자를 정한다. 키가 없으면 안전한 생성·보관 방법부터 별도 승인 후 진행한다. 개인키를 APK나 소스에 넣지 않는다.

## SDK 및 권한: 설치 성공과 사용 승인 구분

현재 의존성은 `NaviHelper:3.0.5`, `FusedLocation:1.1.3`, Android `android.car` API다. 실제 장비의 서비스·API 지원 및 버전 호환성은 별도로 확인해야 한다.

| 항목 | 현재 사용 목적 | 실차·출시 확인 |
| --- | --- | --- |
| `CAR_POWERTRAIN` | `GEAR_SELECTION` 읽기 | 실제 사용자 프로필에서 읽기 가능, 오류·미지원 시 잠금 |
| `CarUxRestrictionsManager` | 플랫폼 주행 제한 | 실제 정책·지역·카테고리별 제한을 따르며 해제 우회 금지 |
| `NAVI_ROUTE` | 안내 정보 확인 | 서비스 연결·권한·응답 내용 확인 |
| `NAVI_ROUTE_SEARCH` | 목적지/경유지 경로 요청 | 기존 경로 변경은 명시적 사용자 동작, 완료 콜백과 목적지 일치 확인 |
| `NAVI_CUSTOM_MAP` | 기본 내비 화면 요청 | 화면 열림을 경로 확인이나 지도 정상 동작으로 오인하지 않음 |
| `FUSED_LOCATION` | 위치 수신 및 로컬 코스 비교 | dangerous 런타임 권한, 차량 개인정보 설정, 프로젝트 제공 상태를 모두 확인 |
| `INTERNET` | 공개 지도·관련 콘텐츠 | 최종 버전의 실제 목적지/데이터 흐름을 목록화하고 정책·서비스 약관과 대조 |

**위치 SDK 제공 상태가 별도 차단 요인이다.** 공식 프로젝트 가이드는 확인일 현재 FusedLocation을 `Not Available Yet`로, Vehicle State와 NaviHelper를 `Ready to Use`로 설명한다. 실제 프로젝트 상태가 우선이며 이 문서 작업에서는 로그인하여 확인하지 않았다. `Not Available Yet`이면 신청 버튼이 없고 `Request Required` 전환을 기다려야 한다. `Affiliation Required`로 표시된 기능만 별도 제휴 절차가 필요하다. SDK 라이브러리 다운로드나 에뮬레이터 GPS 성공이 실차/상용 사용 허가를 증명하지 않는다. [S1]

FusedLocation의 권한 거부·철회·개인정보 설정 차단·null·오류를 처리해야 한다. Android/Google 위치 API의 권한·백그라운드 동작을 Pleos 보장사항으로 가정하지 않는다. [S2] SDK에 미터 단위 정확도와 검증된 시각 의미가 없다는 현재 증거로 실방문 스탬프를 발급하지 않는다.

## 현재 작업과 향후 설치·배포 경로

현재 실행 범위는 1번이다. 2~5번은 향후 승인·장비·서비스 제공 조건이 갖춰지고 별도로 진행을 결정할 때의 경로이며, 이번 작업의 완료를 위해 사용자가 즉시 수행할 단계가 아니다.

1. **개발 준비:** 에뮬레이터에서 최종 변경의 테스트/lint/build를 실행하고 commit, 빌드 버전, 의존성, 테스트 결과를 묶는다. 개인 위치가 포함되지 않은 재현 절차와 안전 실패 케이스를 준비한다.
2. **실물 정차 시험:** 위 장비·접근 허가 및 공급자 설치 절차를 확보한 뒤 지정된 아티팩트와 서명을 검증하고 설치한다. 이 문서에는 실제 차량용 ADB 설치 명령을 제공하지 않는다. 현재 실제 설치 경로는 미확정이다.
3. **통제된 차량 시험:** 아래 합격 기준을 실제 장비에서 실행한다. 안전 제한 오작동·잘못된 경로 확정·위치 노출이 발생하면 시험과 배포를 중단하고 수정한다. 운전자가 화면을 보거나 조작하며 증거를 수집하지 않는다.
4. **스토어 준비:** 공식 배포 경로는 Pleos App Market Console의 앱 심사다. 배포용 서명 APK가 필요하며 debug 키를 사용하지 않는다. [S3][S4] 개발자·국가/카테고리·IARC 등급 증빙·권한/SDK 정보·위치 이용 여부·지원 연락처·심사 설명을 준비한다. 개인정보처리방침 URL이 필요하고 위치/GPS를 사용하는 현재 범위는 위치정보 이용약관 URL도 준비해야 한다. 로그인 기능이 없다면 불필요한 심사용 계정을 새로 만들지 않는다.
5. **제출·출시:** APK 최대 600 MB, 아이콘 512×512 및 최대 1 MB, 스크린샷 최대 8장/장당 8 MB 등 현재 콘솔 요구를 확인한다. 화면 크기 규격은 콘솔에서 다시 확인하고 기존 에뮬레이터 캡처를 자동 적합으로 보지 않는다. 승인된 최종 자료만 제출하고 심사 통과·지원 차종/지역 확인 전에는 출시 완료라 하지 않는다. [S3]

계정 생성·정식 키 생성·서명·업로드·스토어 제출·공개 정책 게시·제휴 문의는 이번 작업에서 실행하지 않았다. 계정이나 공급자 권한이 필요한 단계는 사용자와 정확한 범위를 확인한 뒤 진행한다.

## 실차 합격 기준 및 필요한 증거

아래는 향후 실물 검증 기회가 생겼을 때 사용할 프로젝트 시험 계획이다. 공급자의 공식 인증 절차를 대체하지 않는다. **현재 모든 실차 항목의 상태는 Not Run(미실행), 사유는 시험 차량 사용 불가**다. 지금은 각 항목의 코드/단위 테스트/에뮬레이터 근거를 최대한 보강하며 이 상태를 실차 Pass로 바꾸지 않는다. 향후 실행한다면 검증 환경의 모델/지역/OS/서비스/패키지 버전, commit 및 APK SHA-256, 권한 상태, 시각과 관찰자, 기대/실제 결과, 민감정보 제거 증거 위치를 결과마다 기록한다.

| 시험 | 합격 기준 | 현재 증거·부족한 것 |
| --- | --- | --- |
| 설치/콜드 스타트/업데이트 | 승인된 서명으로 설치·실행, 예상 데이터 보존, 차량 서비스 미지원 시 안전 표시 | unsigned release 컴파일만 기존 통과. 실물·서명·허용 설치 절차 없음 |
| P에서 정상 사용 | 실제 P + UX 제한 해제에서만 탐색·편집 가능 | 기존 에뮬레이터 통과. 실제 gear/UX 증거 없음 |

| 개별 목적지 내비 | fresh 완료 콜백 + 실제 목적지 일치, 요청/화면 열림만으로 성공 표시 금지 | 담양 3개 목적지 에뮬레이터 통과. 실물 provider 미검증 |
| 전체 코스 내비 | 목적지와 순서 있는 모든 경유지 실제 응답 검증. 부족하면 미확인 유지 | 공급자 `(0,0)` 좌표 문제 미해결. 이름만 일치·요청 좌표 복사로 통과 금지 |
| 자동 왕복시간 | 출발·코스·복귀 구간, 데이터 출처/조회시각/교통 반영 여부가 분명하고 일부 실패를 총시간 확정으로 표시하지 않음 | 최종 기능 구현/시험 결과 필요. 실차 현재위치·실시간 교통 정확성은 별도 검증 |
| 실제 방문 판정 | 정확도·신선도·연속 경로 확인 근거 없으면 방문 인증/스탬프 미발급 | 로컬 근접 비교는 실방문 증거 아님. 적절한 센서 계약/시험 데이터 필요 |
| 화면/접근성/주행 주의분산 | 지원 디스플레이와 글자 크기에서 오버플로 없음, 운전 제한/터치 대상/복귀 흐름 확인 | 에뮬레이터 화면 검증만 존재. 차종별·카테고리 심사 필요 [S5] |
| 네트워크/성능/장시간 | 네트워크 끊김과 느린 응답에 안전한 상태, ANR/crash 없음, CPU/메모리/발열의 공급자 기준 충족 | 실물 장시간 자료·공급자 합격 한도 없음. 임의 인증 수치 만들지 않음 |
| 보안/개인정보/데이터 삭제 | release에서 SIM 우회·debug 인증서·비밀 없음, 최소 권한, 외부 전송/저장 정책 일치, 삭제 검증 | backup 비활성·로컬 저장 구현. 최종 release 감사·정책 게시·운영 증거 필요 |

## 지금 대신 준비할 수 있는 일과 중단 경계

- 소스 안전성·실패 상태 개선, 단위 테스트 및 에뮬레이터 회귀 시험, SDK 계약 조사, 익명화 재현 절차, 이 합격 매트릭스와 출시 자료의 초안 작성은 장비 없이 진행 가능하다.
- signed APK 검증·설치 지원·실물 로그 분석은 사용자 승인, 승인된 접근 경로와 실제 장비가 준비된 뒤 가능하다. 새 키 생성·지속 접근 설정은 별도 승인 전 실행하지 않는다.
- 공급자 경유지 문제의 제보 초안은 만들 수 있지만 외부 전송은 수신자·내용 승인 후 수행한다. 실제 위치나 로그를 동의 없이 전송하지 않는다.
- 별도 클라우드 계정/백엔드/결제는 로컬 가족 계획 기능의 필수 전제가 아니다. 동기화·공유·상용 경로 API를 추가한다면 데이터 흐름, 운영자, 비용·약관·비밀 관리·삭제 정책을 먼저 정한다. 무료 공개 지도/경로 서비스의 개발 성공을 상용 SLA·라이선스 확보로 오인하지 않는다.
